## ladder

### a committed `.gitignore` ignores `.claude/worktrees/` and not the rest of `.claude/`
- narrow "No committed `.gitignore` ignores": Does the `.gitignore` at the repository root have a line for the worktrees folder?
- narrow "but that rule isn't committed": Is the rule saved in `.gitignore` but not committed yet?
- narrow "Only `.git/info/exclude` ignores": Is the rule only in a file Git never commits?
- narrow "would hide the settings you share with your team": Does the rule cover more of `.claude/` than the worktrees folder?
- hint: "A committed `.gitignore` at the repository root ignores `.claude/worktrees/`, and nothing else in `.claude/`."
- back: W2 Ask Claude again for the rule, at the repository root, and the commit.

### `main` has both jobs, each made on a branch of its own that split from the other: the comment fix in `src/links.js` and a test that reads `pages/schedule.md`, neither changing the other's file
- narrow "This folder has no": Is this the lab's practice copy, with the website repository in it?
- narrow "This is a worktree": Did you run the check from your main checkout?
- narrow "Start the comment fix's session": Did the comment fix's session start, in `comments-fix`?
- narrow "Start the schedule test's session": Did the schedule test's session start, in `schedule-test`?
- narrow "has no commit of its own": Has that session committed yet?
- narrow "which isn't merged": Is that branch merged into `main` yet?
- narrow "holds both jobs": Did one session get both jobs?
- narrow "the comment fix's file": Did the schedule session change `src/links.js`?
- narrow "the schedule test's file": Did the comment session change the schedule test?
- narrow "one after the other on one line of history": Was each job made in its own worktree, at the same time?
- back: Y1 Give each session only its own job.

### on `main` the tests pass, a link inside an HTML comment is no longer reported, and the schedule test fails when a summer date is missing from the page
- narrow "did not finish": Did `npm test` run to the end?
- narrow "`npm test` fails on `main`": Which test fails first on `main`?
- narrow "crashed": What does the first error from the link checker say?
- narrow "inside an HTML comment": Does the fix skip comments over several lines too?
- narrow "outside any comment": Does the fix skip more than the comment itself?
- narrow "on a page where only": Does the checker report links that resolve?
- narrow "the tests still pass": Does the schedule test check all three dates?
- back: Y3 Read again what each session changed before it committed.

### neither worktree is still there once both branches are merged
- narrow "before you remove either worktree": Are both branches merged into `main` yet?
- narrow "still running": Is a session still open in that worktree?
- narrow "is still there and locked": Did a session leave its worktree locked?
- narrow "whose folder is gone": Did a worktree's folder go without Git removing it?
- narrow "is still there:": Is a worktree still there after its branch merged?
- back: Y4 Merge both branches before you remove anything.
