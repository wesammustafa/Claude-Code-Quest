## intro
- minutes: "about 25 minutes"
- why: "On 11 June the run's report had said "denied: july.md" every morning for two weeks, and nobody knew what that meant. A workflow without its limits written down is trusted for things it never did."
- can: "write down what a workflow checks, what it can't, who decides and how to stop it"
- can: "share it at the right scope, so the limits hold on a teammate's machine"
- can: "use a teammate's dry run to find the limit you didn't write down"
- payoff: "use a teammate's dry run to find the limit you didn't write down"
- read: "[Permissions](https://code.claude.com/docs/en/permissions): how deny, ask and allow rules combine across settings files."

## warm-up

### R1 | Warm-up | Where to read what was refused
- tier: challenge
- skill: watch-run
- from: a-9
- beat: ask
- ask: Where do you find out what a headless run was refused?
- right: The result's permission denials, which name each refused call
- wrong: The run's own summary in its `result` text
- because: "The `result` text was written by the run it describes, and it can leave a refused call out."
- wrong: The exit status: a refused call makes it non-zero
- because: "In `dontAsk` mode a refused call doesn't change the exit status. The run carries on."
- reveal: "The denials list is the run's own record of what it was stopped from doing."

### R2 | Warm-up | A run that says success
- tier: challenge
- skill: headless-run
- from: a-9
- beat: ask
- ask: A refresh ends in success, with one permission denial. Maya asks if the pages are ready to publish. What do you tell her?
- wrong: Yes: `success` means the run did everything it was asked to do
- because: "`success` means the run ended normally. A refused call doesn't stop a run, so part of the job can still be undone."
- right: Not yet: a call was refused, so check which page before anyone uses them
- wrong: No: a run with a denial crashed, so none of its pages can be used
- because: "It didn't crash. It ended normally, and one call was refused along the way, so most pages may be fine."
- reveal: "Read the denials every time, not just how the run ended."

### R3 | Warm-up | A run that stopped early
- tier: challenge
- skill: stop-run
- from: a-9
- beat: ask
- ask: A run to refresh three pages stops at its turn limit after two of them. What's the right recovery?
- wrong: Rerun all three pages with no turn limit, so it can't stop again
- because: "With no limit, nothing stops a run that goes wrong. And two of the pages are already done."
- wrong: Rerun in `bypassPermissions` mode, so nothing gets in its way
- because: "The run wasn't blocked by a rule: it ran out of turns. `bypassPermissions` approves everything the deny rules leave out, so the allow list stops fencing the run."
- right: Rerun only the page it left, with the same bounds and enough turns for one page
- reveal: "Rerun what failed, keep the bounds, and size the limit to the job."

## ladder

### `LIMITS.md` says what the run does, what it can't, who decides and how to stop it, names unsaved changes and registrations, and is in the shared version
- narrow "There's no": Did Claude save the card in `fixit/summer/`?
- narrow "not the venues' latest word": What does the run actually read?
- narrow "doesn't say what the run does": What does the card say the run does?
- narrow "doesn't say what the run can't": Where does the card list what the run can't do?
- narrow "who decides": Who reads the report, and who publishes?
- narrow "how to stop": What stops the runner starting?
- narrow "phone call": What happens to a change nobody saved in `summer/`?
- narrow "registration": Which number can the run never see?
- narrow "isn't in the shared version": Did you save a version teammates get?
- narrow "shared version still": Does the saved version have the corrected card?
