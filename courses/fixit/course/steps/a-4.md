## intro
- minutes: "about 25 minutes"
- why: "Ade wants Claude to review each change before anyone commits it to the website repository, with nobody at the keyboard: no edits, no surprises, and a failed review that stops the commit."
- can: "run Claude Code from a script with nobody at the keyboard"
- can: "bound what the run may do: its mode, its tools and its turns"
- can: "get Claude's answer in a shape you define, with a JSON Schema"
- can: "make a failed or capped run fail loudly, and check a review before you act on it"
- payoff: "run Claude Code from a script with nobody at the keyboard"
- need: "bash and `jq`, on macOS, Linux or WSL 2: the practice workspace has both."
- read: "[Run Claude Code programmatically](https://code.claude.com/docs/en/headless): `-p`, its output formats and the flags that bound a run."

## steps

### W1 | Worked example step 1 of 3 | Decide first: is a successful run done?
- tier: challenge
- skill: ask
- where: terminal
- beat: ask
- ask: A run that nobody watched ends with JSON that says `"subtype": "success"` and lists one call in `permission_denials`. Is the job done?
- wrong: Yes: success means the job is done
- because: "Success means the run ended normally. A denial means Claude tried something your rules refused, so part of the job may be missing."
- right: Not until you've read the denial
- wrong: No: a run with any denial failed, so run it again
- because: "A denial can be fine, when Claude tried something it didn't need. Read which call was refused."
- reveal: "`"subtype": "success"` says only that the run ended normally. Read the exit code, `is_error` and `permission_denials`, then the result, before you trust a run nobody watched."

### W2 | Worked example step 2 of 3 | Run with nobody to approve
- tier: guided
- skill: headless-run
- where: terminal
- beat: do
- verify: json .practice/a-4-denied.json permission_denials.0 fresh
- goal: "In the terminal, ask Claude to run the tests, with nobody there to approve the command, and save the JSON:"
- code: point 1
```bash
claude -p "Run the tests and say how many pass" --output-format json --permission-mode dontAsk > .practice/a-4-denied.json
jq -c '.permission_denials[] | {tool_name, command: .tool_input.command}' .practice/a-4-denied.json
```
- why: "Nobody can answer a permission prompt in a script, so pass a mode every time: `dontAsk` denies whatever would ask, and lists it."
- note: "`-p` runs Claude once, prints its answer and exits. `--output-format json` makes that answer one JSON object, and `jq` picks fields out of it."
- note: "`.practice/` is a folder Git ignores, for files like this one."
- note: "Each `-p` run is a fresh session, as in Lesson 5: it knows only the files and the prompt."
- beat: do
- verify: self
- done-label: I read the result
- goal: "Then read how the run ended, and what it says:"
- code: point 1
```bash
jq '{subtype, is_error, result}' .practice/a-4-denied.json
```
- expect: "`"subtype": "success"` and `"is_error": false`, and a result that says Claude couldn't run the tests. Success means the run ended normally, not that the job got done."

### W3 | Worked example step 3 of 3 | Allow one command, then cap the turns
- tier: guided
- skill: limit-run
- where: terminal
- beat: do
- verify: json .practice/a-4-allowed.json permission_denials=[] fresh
- goal: "Allow the one command the job needs, cap the turns, and run it again:"
- code: point 1
```bash
claude -p "Run the tests and say how many pass" --output-format json --permission-mode dontAsk --allowedTools "Bash(npm test)" --max-turns 3 > .practice/a-4-allowed.json
jq '{subtype, num_turns, denied: (.permission_denials | length), result}' .practice/a-4-allowed.json
```
- why: "One precise rule allows the test command and nothing else, and `--max-turns` stops a run that wanders: by default there is no limit."
- expect: "`"subtype": "success"`, `"denied": 0`, and a result that counts the passing tests."
- beat: predict
- ask: Claude reads `package.json` to find the test command, then runs it. With `--max-turns 1`, what will the saved JSON show?
- option: A success, with the count
- because: "`--max-turns 1` allows one turn. Reading `package.json` takes it, so the tests never run."
- right: A stop at the cap, with no result
- option: A failure message in its result
- because: "A run stopped at its cap has no `result` at all."
- reveal: "A run that stops at the cap ends with `error_max_turns` and has no `result`: read `subtype` before you read `result`."
- beat: do
- verify: json .practice/a-4-capped.json subtype=error_max_turns fresh
- goal: "Cap it at one turn:"
- code: point 1
```bash
claude -p "Run the tests and say how many pass" --output-format json --permission-mode dontAsk --allowedTools "Bash(npm test)" --max-turns 1 > .practice/a-4-capped.json
echo "exit $?"
jq '{subtype, is_error, has_result: has("result")}' .practice/a-4-capped.json
```
- note: "It exits with 1, and `is_error` is `true`: a script that checks either one stops here."
